# APEX 6 Pro PCM 실시간 설정

## 동작 및 범위

- 기존 76바이트 PCM 측정 IPC와 독립된 세션 전용 제어 IPC를 사용합니다.
- Tray의 `ResolveApex6PcmPolicy()`가 전역/게임별 설정과 해당 게임의 기준 피크를 합성합니다. 전역 설정 변경도 현재 활성 게임 기준으로 재계산합니다.
- 엔진은 프로토콜 버전, 게임 키, 설정 범위와 요청 번호를 검증한 뒤 렌더링 블록 경계에서 적용합니다. 성공 표시는 전송 완료가 아니라 엔진 적용 ACK를 기준으로 합니다.
- 제어 매핑은 `Local\ApexSenseBridge.Session.<token>.Apex6PcmControl` 및 별도 `.Mutex`를 사용합니다. 프로토콜 v1은 308바이트이며 요청/ACK 번호와 게임 키, 최종 정책을 전달합니다. 한글 게임 키가 Windows 명령줄 코드 페이지에 의해 손상되지 않도록 시작 시에는 UTF-8 바이트의 16진수 인자 `--apex6-pcm-game-key-hex`로 전달합니다.
- 설정 전달이 실패해도 기존에 적용된 정책은 유지됩니다. 저장된 정책과 현재 엔진 정책은 연결 오류 동안 다를 수 있으므로 UI 적용 상태를 확인해야 합니다.
- 일반 럼블, 적응형 트리거, 다른 APEX 모델은 변경 대상이 아닙니다. 원본 48kHz 피크 측정 및 측정 시작/종료/저장 프로토콜은 유지합니다.

## 실제 게임/하드웨어 확인 체크리스트 — 미검증

자동 테스트만으로 아래 항목을 완료 처리하지 않습니다. APEX 6 Pro 실물과 PCM 지원 게임에서 별도로 확인해야 합니다.

1. 게임 및 브리지를 종료하지 않고 Original → Companding → Linear → Normalize → Original로 전환합니다. 엔진 ACK 후 UI가 적용 완료를 표시하고 실제 진동이 바뀌는지 확인합니다.
2. Linear/Companding 배율과 Normalize 목표·상한 슬라이더를 빠르게 연속 조작합니다. 마우스를 놓은 최종 값이 적용되고 프레임 지연·진동 끊김·강약 및 타이밍 손상이 없는지 확인합니다.
3. 기준 피크를 직접 입력하거나 측정 결과를 저장합니다. Normalize 배율이 즉시 재계산되고 좌우 밸런스가 유지되는지 확인합니다.
4. 측정 중 모드·배율을 바꿉니다. 좌우 원본 피크, 원본 48kHz 측정, 종료 ACK 및 저장 검증이 정상인지 확인합니다. 변경 후에도 피크 측정은 출력 배율이 아닌 원본을 기준으로 해야 합니다.
5. 게임별 설정과 전역 상속을 번갈아 사용하고 전역 PCM을 끕니다. 활성 게임이 Original로 돌아오며, 다른 게임을 선택해 수정해도 활성 게임에 다른 게임의 기준 피크가 전달되지 않는지 확인합니다.
6. 게임 세션 종료·재시작과 연결 끊김·재연결을 시험합니다. 연결이 없으면 적용 완료로 표시하지 않고 새 세션에서 새 정책 ACK를 받아야 합니다. 이전 세션의 늦은 ACK가 새 세션의 성공 표시로 사용되면 안 됩니다.
7. 호환되지 않는 이전 엔진과 연결하면 성공 대신 연결/버전 오류를 표시하는지 확인합니다. 정상 엔진 재실행 후 복구되는지도 확인합니다.
8. 강한 후반 진동에서 클리핑 포화 및 최대 증폭 상한이 유지되는지, 약한 진동과 이벤트 순서가 보존되는지 확인합니다.
9. 동일 게임의 일반 럼블·적응형 트리거, 다른 APEX 모델의 기존 출력이 변하지 않았는지 확인합니다.

## 자동 검증과 실기 검증의 경계

네이티브 테스트는 실제 Windows 공유 메모리·별도 스레드 Mutex 경합·ACK/오류/재연결 및 가짜 HID 전송 계층을 통한 모드별 출력 값을 검증합니다. 관리 코드 테스트는 실제 제품 정책 계산과 공유 메모리 클라이언트, 디바운스 동작을 검증합니다. 이 테스트들은 실제 WPF 마우스 조작이나 USB 장치의 출력 지연을 측정하지 않으며, ThreadSanitizer로 데이터 레이스 부재를 증명하는 시험도 아닙니다. 실물 장치 확인 전에는 물리 출력·체감 지연을 미검증으로 취급합니다.
